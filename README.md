# OpenEndRPG · 完全开放式RPG

**一个"只提供开头"的文字冒险游戏：任务、NPC、事件——后续的一切内容，全部由 LLM 根据你的输入即时生成。画面也是：一张由汉字排布成的"字画幻灯片"，随剧情同步切换。**

无美术、无图像服务、无预设剧情树；剧情长度不设上限，靠世界状态账本与滚动摘要保证长线连贯。终端与网页两种玩法，共用同一套引擎。

> 想法与调研笔记（中文）：本项目是"完全开放式RPG"想法的最小原型。原型设计沿用三条研究结论：**叙事归 LLM、状态归确定性代码**（Song et al. 2024, [arXiv:2409.06949](https://arxiv.org/abs/2409.06949)）、**两级滚动记忆**（Zhou et al. 2023, [arXiv:2305.13304](https://arxiv.org/abs/2305.13304)）、**常驻 NPC 记忆流**（Park et al. 2023, [arXiv:2304.03442](https://arxiv.org/abs/2304.03442)）。

## 玩法核心

- **开局只有一段序章**：黑曜王座上的大魔王苏醒，村长交给你一柄祖传短剑——之后世界没有任何预设内容。
- **自由输入驱动**：每回合输入任意行动（自然语言），游戏主持人（LLM）生成本回合**后果叙事**与 **2–4 条下一步建议**（建议仅供快速选择，随时可以无视它自由发挥）。
- **字画幻灯片（网页模式）**：LLM 在生成剧情的同一次调用里兼任"画面导演"，输出 0–3 张 12×6 字符画布——"主角往前走"就是「我」字在画布间平滑移动，"发现宝箱"就是「宝箱」二字被字拼的箱体围住；画面以 PPT 式切换（淡入/平滑滑动，无逐字动效）。前端不含任何形状库或图片，所有画面 100% 来自模型输出。
- **NPC 常驻可重逢**：登场过的 NPC 全部常驻世界账本（上次见面时间、见面次数、近况笔记）；隔了几天再回去找他们，他们会带着这段时间各自的生活近况与你重逢，关系随见面累积——NPC 不是一次性用品。
- **一天规则**：除非你明确要求跳时间（如"三天后"），每回合只推进"一天以内"的游戏时间——剧情以天为单位徐徐展开。
- **命运骰**：每回合暗掷一枚 d20（意外挫折 / 平淡进展 / 小机遇 / 重要转机 / 命运大事件五档倾向）注入生成，同样的输入会有不同的走向；`/reroll` 可换骰重演本回合。
- **无限剧情**：世界账本（事实 / NPC / 物品 / 时间）由确定性代码合并入档，滚动剧情摘要 + 最近回合原文注入上下文，每回合自动存档。

## 快速开始

```bash
git clone https://github.com/9M-XXB/OpenEndRPG.git
cd OpenEndRPG
python3 rpg.py          # 终端模式：首次运行自动进入 API 配置向导
python3 rpg.py --server # 网页模式：浏览器打开 http://127.0.0.1:8770 即玩（含字画幻灯片）
```

依赖：Python 3.10+ 与 `httpx`（`pip install httpx`；可选 `pip install rich` 获得更好的排版，缺失时自动降级为纯文本）。网页服务与前端只用 Python 标准库与原生 HTML/CSS/JS，无需安装浏览器端任何东西。

`--server` 常用参数：`--new 存档名` / `--save 存档名`（缺省自动载入最近存档或新建）、`--port`、`--host 0.0.0.0`（允许同局域网设备访问）。

## 支持的 API（14 预设 × 3 类协议，零 SDK 依赖）

| 协议 | 预设 |
|---|---|
| OpenAI 兼容 | OpenAI / DeepSeek / Kimi(Moonshot) / 智谱 GLM / 通义 Qwen / OpenRouter / Groq / SiliconFlow / **Ollama 本地** / LM Studio 本地 / 自定义端点（vLLM、one-api、中转均可） |
| Anthropic | Claude |
| Google | Gemini |
| 离线 | Mock（免 key，脚本化剧情，用于测试与演示） |

首次运行向导：选服务商 → base_url（回车用默认）→ API key → 模型（自动在线拉取列表选择）→ 测试对话 → 保存到 `config.json`。随时 `python3 rpg.py config` 重新配置。

> **隐私**：API key 只保存在本机 `config.json`（已被 `.gitignore` 排除）；`config.example.json` 是字段模板。

## 游戏内命令

| 命令 | 作用 |
|---|---|
| `/help` | 帮助 |
| `/status` | 查看世界账本（天数/地点/事实/NPC/物品/摘要） |
| `/roll` | 查看上回合命运骰 |
| `/reroll` | 撤销本回合，换骰重演 |
| `/suggestions` | 重显上回合建议 |
| `/save` · `/quit` · `/config` | 手动存档 · 存档退出 · 重配 API |

直接输入 `1`/`2`/`3` 可快速采用上回合建议；其余一切输入都是你的行动。

## 项目结构

```
OpenEndRPG/
├── rpg.py       # 入口：主菜单、API 配置向导、--server 网页模式
├── engine.py    # 游戏主循环、命令、快照重掷
├── llm.py       # 三类协议客户端、14 预设、SSE 流式、JSON 解析与自修复、Mock
├── state.py     # 存档读写、世界账本确定性合并、时间推进
├── prompts.py   # GM 系统规则（含【画面幻灯片】教学节）、序章、命运骰表、上下文组装
├── ui.py        # 终端渲染（rich/plain 双模式，打字机效果）
├── webui.py     # Web 事件适配器：与 ui.py 同方法面，把渲染调用收集为事件
├── server.py    # 本地 Web 服务（标准库 HTTP，GET /api/state + POST /api/say）
├── web/         # 前端（原生 HTML/CSS/JS，零构建）
│   ├── slides.js  # 字画幻灯片引擎：画布归一化 + 按字匹配的 PPT 式切换（零图像元素）
│   ├── app.js     # 客户端逻辑：状态拉取、回合渲染、打字机、建议 chips
│   ├── index.html / style.css
├── config.example.json
└── saves/       # 存档目录（运行时生成，不入库）
```

每回合流程：玩家输入 → 深拷贝快照 → 掷命运骰 → LLM 输出严格 JSON（叙事 + 字画幻灯片 + 时间增量 + 状态增量 + 滚动摘要 + 建议，失败自动带错误重试修复）→ **确定性代码**校验并合并状态（幻灯片只做宽松钳位，画面失败不使回合失败）→ 呈现叙事与字画 → 自动存档。

**画面契约**：`slides[] = {caption, tone(暗/明/暖/冷/灰), canvas: 6 行 × 12 字符}`；画布规格常量在 `prompts.py`（`CANVAS_W/CANVAS_H`），前后端共用；主角固定「我」、NPC 用名字首字、上北下南左西右东、移动 1–2 格严禁瞬移——这些规则写在 `prompts.py` 的【画面幻灯片】节，是教运行时 LLM 作画的唯一出处。
